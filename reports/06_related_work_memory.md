# 相关工作：智能体记忆与安全（2026-10-31 检索）

**检索目的**：确认"探索时不安全的成功被写进 Harness VLA 的记忆、再传到评估"这一点有没有人做过。

**检索方式**：子代理用网络检索完成，查询词和打开过的页面见本文末尾。有些论文只读了摘要，下文逐条注明。

## 结论

- 没有找到完全相同的工作，即同时满足下面两点的：
  1. 在冻结 VLA 的 Harness 上证明：碰撞的成功探索写进记忆后，评估阶段碰撞变多；
  2. 在写入记忆时做安全审计。
- 但"只按成功筛选的经验或技能积累，会存下不安全做法"这个概念，在**软件类 LLM 智能体**上已经有充分研究。
- 所以新意不能靠概念本身，只能来自三点：机器人和 VLA 场景、以物理碰撞定义"不安全"、在同一场景上的因果证据。

## 还剩下的区分点

1. **自己产生的污染**：没有攻击者，是智能体自己在物理环境里碰撞的经验进入记忆。已有工作要么是攻击，要么是语义安全，要么是软件智能体。
2. **同一场景上的因果证据**：干净记忆对污染记忆（`05_memory_control.md`），以后再区分 task-specific 和 global 两种记忆。SafeHarness 只说明了"无障碍场景的旧技能有害"。
3. **基于碰撞信号的写入审计**：用接触或障碍物位移作为信号，并且回溯清理从不安全成功中学到的 global 规则。这是和 Skill Misevolution 用 LLM 判断的主要区别。
4. **不重训 VLA**，并且可以和 SafeHarness 的运行时检查一起使用，说明二者互补。
