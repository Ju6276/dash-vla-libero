# DASH 模块的离线验证

不调用规划器、不消耗 Codex 额度，先检查每个候选模块的前提是否成立。候选模块见 `00_current.md` 之后的设计讨论：
1. 场景危险清单：不让规划器自己挑障碍物，而是把任务没提到的物体全部框出来。
2. VLA 执行中的监控。
3. 按手腕朝向调整安全距离。
4. 写入记忆前的安全审核。

## 模块 1：场景危险清单（2026-10-30）

做法：`scripts/safelibero/offline/run_hazard_inventory.sh`。
- 场景：8 个套件 × task 0–3 × episode 0–1，共 64 个初始场景。
- 输入只用 Harness 能看到的东西：`ground_box` 所用的 1024 高清视角图和对应的三维点云，以及规划器观测里的物体名单（已去掉 `obstacle` 标记）。
- 清单规则：物体名的名词（如 `moka_pot_1` 的 `pot`）不在任务语句里，就列为危险物。提示词由物体名生成，去掉 small、large 等描述大小的词。
- 包围盒和 `ground_box` 完全相同（掩码三维点的 2%–98% 分位数）。仿真器真值只用来评分。

| | 结果 |
|---|---|
| 障碍物被列入清单 | 64/64 |
| SAM3 框得出来 | 58/64 |
| 中心水平误差 ≤ 5 cm | 56/64（88%） |
| 中心水平误差中位数 | 1.2 cm |
| 每个场景的危险物数量 | 平均 4.8 个 |

- 没框出来的 6 个：goal_I task 3 的两个 episode，long_II、object_II、spatial_II、spatial_I 各 1 个。
- 框错的 2 个：goal_II task 0 和 3 的 episode 0，摩卡壶的框偏了 15–18 cm，框到了别的物体上。
- 用原始物体名做提示时只有 53/64 框得出来。失败多来自 `moka_pot_small` 这类带大小修饰词的名字，去掉修饰词后补回 5 个。
- 摩卡壶的框顶部系统性偏低约 2 cm（顶部从这个视角看不全）。对"障碍物上方 5 cm"这条规则有影响，需要留余量。

读数：
- "把任务没提到的物体都当成危险物"在 SafeLIBERO 上能完全覆盖真正的障碍物。剩下的问题在感知：约 12% 的场景要么框不出来，要么框错。要补上这一块，可以加手腕相机视角，或者用点提示重试。
- 对比：正式轮 B2 的规划器在 spatial_I 两个回合中有一个漏框了真正的障碍物。样本太少，还不能拿这一点和本节的 88% 比较。
- 代价：每个场景平均 4.8 个危险物。如果每个都按 SafeHarness 的 12 cm 规则处理，路线会更难规划，这要看模块 3。
